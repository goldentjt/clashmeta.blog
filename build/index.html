Clash Meta教学
从最小配置到可验证结果

围绕 Clash Meta（Mihomo）内核与客户端配置，提供版本明确、输入透明、可对照输出与支持一键回退的完整技术教学实验。 每个网络概念均配套最小 YAML 配置、抓包检验方法以及系统网络恢复步骤，杜绝抽象猜测，让读者每一次连接调优都能落到实处。

实验前置导读：前置阅读 → 代理基础 (/proxy-basics/)|下一步操作 → Meta教程 (/getting-started/)|节点配套 → 机场推荐 (/airport-recommend/)

确定核心与客户端

在开展任何代理网络调优实验前，必须先厘清核心（Core）与图形客户端（GUI）的权责边界。 Clash Meta（现演进代号为 Mihomo）负责解析 YAML 规则、管理 TCP/UDP 虚拟网络栈、执行 DNS 分流与出站握手； 而 Clash Verge Rev、Clash for Windows 等客户端则主要承担配置文件的覆写、系统代理注册与图形化仪表展示。 固定所使用的内核版本（如 v1.18+ 或稳定发行版），是保障教程配置具有可复现性的首要基线。

选实验起点

新手切忌直接引入包含数千条规则的臃肿混合订阅。推荐按以下梯度循序渐进：

① 最小基线实验

从仅有 1 个 Direct 直连与 1 个测试节点的单文件开始，验证 7890 端口监听与系统连通。

② 代理集合解耦

使用 proxy-providers 将机场节点集与本地分流规则解耦，实现节点更新不影响路由策略。

③ 系统栈与TUN劫持

开启虚拟网卡接管全系统网络流量，规避浏览器代理局限，实测 AI 工具与终端命令行连接。

按前置知识继续学习

如果遇到域名解析超时、节点测试 Timeout 或规则未按预期命中，请立刻回归基线，查阅我们提供的实验排错手册 (/lab-errors/) 与DNS防污染实验 (/dns-lab/)，分段回退定位故障点。
